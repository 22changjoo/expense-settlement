# 목회비·주유비·경비 정산 관리 시스템

영수증을 찍으면 Claude 가 날짜·금액·항목을 읽어 초안을 채우고, 예산 대비 사용액과
정산(입금) 대사를 한 화면에서 확인하는 개인용 PWA 입니다.

| 구분 | 내용 |
|---|---|
| 프런트엔드 | 정적 HTML/CSS/JS (`web/`) — GitHub Pages |
| 백엔드 | Google Apps Script Web App (`apps-script/`) |
| 데이터 | Google Sheets — `경비정산시스템_데이터` |
| 영수증 이미지 | Google Drive `내 드라이브/경비정산_영수증/` (비공개) |
| 자동 분류 | Claude Vision (`claude-sonnet-5`) |

```
경비정산시스템/
├── apps-script/          Apps Script 프로젝트 (clasp push 대상)
│   ├── appsscript.json
│   ├── Config.gs         설정 상수·스크립트 속성
│   ├── Sheets.gs         시트 접근·값 정규화·ID 생성
│   ├── Dates.gs          ISO 주차 계산
│   ├── Drive.gs          영수증/입금캡처 저장
│   ├── Vision.gs         Claude Vision 분석·정기구독 매칭
│   ├── Expense.gs        지출기록 CRUD
│   ├── Settlement.gs     정산 대사
│   ├── Dashboard.gs      예산 집계·정기구독 예상 반영
│   ├── Settings.gs       예산·정기구독·CSV 내보내기
│   ├── Code.gs           doGet/doPost 라우터
│   └── Setup.gs          최초 설치·연간 트리거
└── web/                  PWA (GitHub Pages 배포 대상)
    ├── index.html  styles.css  api.js  ui.js  app.js
    ├── manifest.webmanifest  sw.js  icons/
```

## 1. 설치

### 1-1. Apps Script 프로젝트 만들기

데이터 시트(`경비정산시스템_데이터`)에서 **확장 프로그램 → Apps Script** 를 열고,
`apps-script/` 의 `.gs` 파일을 같은 이름으로 만들어 붙여 넣습니다.
`appsscript.json` 은 **프로젝트 설정 → "appsscript.json" 매니페스트 파일 표시** 를 켠 뒤 교체합니다.

clasp 를 쓰신다면:

```bash
cd apps-script && clasp create --type sheets --title "경비정산시스템" && clasp push
```

### 1-2. 스크립트 속성 등록

편집기에서 `Setup.gs` 의 **`setupScriptProperties`** 를 한 번 실행합니다.
`ANTHROPIC_API_KEY` 는 [Anthropic Console](https://console.anthropic.com/) 에서
발급한 키를 넣습니다(비워 두면 자동 분석만 꺼지고 수기 입력은 그대로 동작합니다).

| 속성 | 설명 |
|---|---|
| `SPREADSHEET_ID` | 데이터 시트 ID. 시트에 연결된 프로젝트면 자동으로 채워지고, 독립 프로젝트면 `setupScriptProperties` 안의 `sheetId` 변수에 직접 넣습니다 |
| `API_TOKEN` | 웹앱 접근 토큰 — 실행 로그에 출력됩니다. 앱 첫 실행 때 붙여 넣습니다 |
| `ANTHROPIC_API_KEY` | Claude Vision 호출용 키 |

이어서 **`setupSheetsAndFolders`** 와 **`setupAnnualTrigger`** 를 한 번씩 실행합니다.
토큰을 새로 발급하려면 **`resetApiToken`** 을 실행하고, 앱 설정 화면에서 다시 입력하십시오.
(시트 4종·Drive 폴더 생성, 매년 1월 예산 행 자동 복사)

### 1-3. 웹앱 배포

**배포 → 새 배포 → 웹 앱**

- 실행 계정: **나** (시트를 소유한 본인 계정)
- 액세스 권한: **모든 사용자**

> "모든 사용자" 는 URL 을 아는 사람이 요청을 보낼 수 있다는 뜻이며, 데이터 접근은
> `API_TOKEN` 으로 막습니다. 토큰이 없으면 모든 요청이 거부됩니다.

배포 URL(`.../exec`)을 복사해 둡니다.

### 1-4. 프런트엔드 배포

**배포 주소: https://22changjoo.github.io/expense-settlement/**

`main` 에 푸시하면 `.github/workflows/pages.yml` 이 `web/` 폴더를 GitHub Pages 로
배포합니다. (Pages 의 폴더 소스는 루트나 `/docs` 만 지원해서, 디렉터리 구조를
유지하려고 Actions 방식을 씁니다.)

배포된 주소를 열면 연결 화면이 뜹니다 — 웹앱 URL 과 API_TOKEN 을 입력하면 끝입니다.
두 값은 그 브라우저의 `localStorage` 에만 저장되며 저장소에는 들어가지 않습니다.

모바일에서는 Safari/Chrome 의 **홈 화면에 추가** 로 설치합니다.

## 2. 화면

| 화면 | 내용 |
|---|---|
| 홈 | 목회비·주유비 예산 게이지, 세부항목 breakdown, 경비 요약, 상태 배지, 최근 5건 |
| 지출 | 항목·기간·상태 필터, 카드 목록, 상세에서 수정·삭제, **영수증 일괄 제출** |
| ＋ | 영수증 촬영/선택 → Claude 분석 → 확인·수정 → 저장 |
| 정산 | 목회비(월 단위) / 경비(주차 단위) 대사, 차액 자동 계산 |
| 설정 | 예산 한도(연도·세부 한도 추가/삭제), 정기구독 추가/삭제, 연결 상태, CSV 내보내기 |

**총액 / 비율 토글** — 목회비 카드 오른쪽 위에서 전환합니다.
"총액" 은 예산 게이지와 세부항목 막대를, "비율" 은 세부항목 구성비 원그래프와 범례를
보여 줍니다. 두 보기 모두 아래의 정기구독 토글을 그대로 따르므로, "실사용만" 을 켜면
구성비도 실제 등록분만으로 다시 계산됩니다. 금액이 0인 세부항목은 원그래프에서 뺍니다.

**영수증 단계** — 지출 한 건은 `미제출 → 정산 대기 → 정산완료`(또는 `금액불일치`) 순서로
지나가며, 카드에는 지금 단계의 배지 하나만 붙습니다. 대시보드 알림과 지출 목록의 상태 필터도
같은 단계로 나뉘어, **한 영수증이 두 목록에 동시에 나오지 않습니다.**

| 단계 | 뜻 | 할 일 |
|---|---|---|
| 미제출 | 아직 회계간사님께 내지 않음 | 일괄 제출 |
| 정산 대기 | 냈지만 아직 입금 전 | 정산 화면에서 대사 |
| 정산완료 · 금액불일치 | 입금 대사 끝 | — |

정산 화면에서 입금 대사할 지출을 고를 때도 **정산 대기인 것만** 나옵니다. 그 기간에 아직 내지 않은
영수증이 있으면 "미제출 N건은 제출완료로 바꾸면 여기에 나타납니다" 라고 알려 주며, 서버도 미제출
영수증을 정산에 묶으려 하면 거부합니다.

예전에는 `정산상태=미정산` 을 모두 정산 대기로 셌고, 카드에 `제출완료`·`미정산` 배지를 나란히
달아 이미 낸 영수증도 미제출로 읽히기 쉬웠습니다.

**영수증 일괄 제출** — 지출 목록에서 상태를 `미제출` 로 보면(대시보드의 `미제출 영수증` 을
눌러도 됩니다) 맨 위에 `영수증 일괄 제출` 이 나타납니다. 누르면 체크 목록으로 바뀌고, 낸 것만
고른 뒤 제출일을 확인해 한 번에 `제출완료` 로 바꿉니다. 취소하면 들어오기 전의 필터로 돌아갑니다.

**정기구독 예상액 내역** — "정기구독 포함" 보기에서 목회비 카드의 `정기구독 예상액` 줄을
누르면 구독별로 펼쳐집니다. 어느 달이 아직 비었고 어느 달은 영수증이 들어왔는지
(`10~12월 · 3개월 × 20,000원 (1~9월 영수증 등록됨)`) 확인할 수 있습니다.

**정기구독 포함 / 실사용만 토글** — 기본값은 "정기구독 포함" 입니다.
아직 영수증이 들어오지 않은 달의 정기구독 예상액을 점선 음영으로 덧그려,
연말까지의 예상 소진액을 미리 보여 줍니다. 해당 월에 `연결구독ID` 로 등록된 실제
지출이 있으면 그 달의 예상액은 빼고 실제 금액만 셉니다.

### 예산 한도

`예산설정` 시트는 연도별 한 행이고, **세부 한도는 열로 늘어납니다**.
설정 화면에서 "세부 한도 추가" 를 누르면 `목회비_<세부항목>한도` 열이 생기고,
삭제하면 그 해 칸이 비워집니다. 어느 해에도 값이 남지 않으면 열 자체가 사라집니다.

- 건강관리 한도를 비워 두면 목회비 한도의 20% 로 자동 계산합니다(교회 규정 기본값).
  값을 직접 넣으면 그 값이 우선합니다.
- 세부 한도는 **연간 누적 기준**입니다. 연중에 새로 걸어도 그 해 전체 사용액과 비교합니다.
- 연도 삭제는 그 해에 지출이 있으면 한 번 막고 다시 묻습니다. 마지막 남은 연도는
  삭제할 수 없습니다.

### 정기구독

목록에서 항목을 탭하면 수정·삭제 시트가 열립니다.

- **해지** 로 두면 예상액 계산에서 빠지고 기록은 남습니다.
- **삭제** 하면 목록에서 사라집니다. 이미 등록된 지출의 `연결구독ID` 는 그대로 두므로
  과거 금액과 내역은 보존됩니다. 삭제 전에 연결된 지출 건수를 함께 보여 줍니다.

## 3. 정산 규칙

```
연결지출합계 = SUM(선택된 지출 금액)
차액 = 입금액 - 연결지출합계

차액 == 0 → 일치       / 선택 지출 모두 "정산완료"
차액 != 0 → 불일치     / 선택 지출 모두 "금액불일치"
```

2026년 1~8월 임포트분은 `정산상태 = 정산확인불가(과거기록)` 이라 정산 화면에
나타나지 않습니다.

## 4. 구현 중 결정한 사항

작업 지시서 §8 의 미결 항목을 다음과 같이 정했습니다. 바꾸실 부분이 있으면 알려 주세요.

1. **Claude API 키** — Anthropic API 키를 Apps Script 스크립트 속성에 두고 서버에서만
   호출합니다. 키가 프런트엔드로 나가지 않으므로 GitHub Pages 에 올려도 안전합니다.
2. **주차 기준** — ISO 8601(월요일 시작)을 씁니다. 저장값은 `2026-W37`,
   화면 표시는 `2026년 9월 2주차 (9/7~9/13)` 입니다. 교회 회계 기준이 일요일 시작이라면
   `Dates.gs` 의 `isoMonday_` 한 곳만 고치면 전체가 따라옵니다.
3. **정산에 묶인 지출 삭제** — 막지 않고 경고 후 진행합니다. 삭제 시 해당 정산기록의
   합계·차액을 다시 계산하고, 남은 지출의 정산상태도 갱신합니다.

## 5. 알아 두실 점

### 영수증 이미지 보관

```
내 드라이브/경비정산_영수증/          ← 코드 폴더(코딩/경비정산시스템)와 이름이 다릅니다
  ├── 영수증/2026/09/               ← {지출ID}_{사용일자}.jpg
  └── 입금캡처/2026/
```

- 폴더는 비공개이며, 앱은 **폴더 ID** 로 찾습니다(`DRIVE_ROOT_ID` 스크립트 속성).
  Drive 에서 폴더를 옮기거나 이름을 바꾸셔도 앱은 계속 같은 폴더를 씁니다.
- 브라우저에서 직접 열리지 않으므로, 상세 화면에서는 Apps Script 를 거쳐 받아 보여 줍니다.
- **PDF 영수증도 올릴 수 있습니다.** 파일 선택에서 PDF 를 고르면 줄이지 않고 원본 그대로
  Claude 에 보내(document 블록) 글자까지 읽게 하고, Drive 에도 `.pdf` 로 보관합니다. 10MB 까지
  받으며, PDF 가 아닌 파일은 보내기 전에 걸러냅니다. 지출 상세에서는 파일 카드와 Drive 링크로 보여 줍니다.
  카메라 촬영은 사진만 받습니다.
- **업로드 전에 용량을 줄입니다.** 긴 변 1400px 부터 시작해 200KB 이하가 될 때까지
  해상도와 품질을 단계적으로 낮춥니다. 4032×3024 / 1.5MB 사진이 1400×1050 / 29KB 로
  줄었고, 상호·사업자번호·날짜·품목·합계가 모두 읽혔습니다. 영수증 200장이 약 10MB 로,
  Drive 용량에 부담이 없습니다.
### 시작 속도

Apps Script 응답은 서버 처리에만 2~4초가 걸립니다(네트워크가 아니라 실행 시간).
그래서 두 갈래로 줄였습니다.

- **서버**: 한 번의 요청 안에서 스프레드시트를 다시 열거나 같은 시트를 다시 읽지
  않도록 실행 단위 캐시를 둡니다(`MEMO_`). 시트를 고치면 그 시트만 버립니다.
  `bootstrap` 이 5.6초 → 3.1초가 되었습니다.
- **앱**: 마지막으로 받은 데이터를 `localStorage` 에 남겨 두고(약 16KB), 앱을 열면
  그 값으로 **즉시 그린 뒤** 뒤에서 새로 받아 옵니다. 갱신 중에는 상단 새로고침
  아이콘이 돕니다. 서버에 닿지 못하면 저장된 내용을 그대로 두고 알림만 띄웁니다.
  화면이 뜨기까지 3~6초 → **약 25ms** 가 되었습니다.

**저장도 기다리지 않습니다.** 지출 수정·일괄 제출은 이 기기의 데이터를 먼저 고쳐 바로
보여 주고, 서버 저장과 합계 재계산은 뒤에서 합니다(새로고침 아이콘이 도는 동안).
실패하면 알림을 띄우고 서버 값으로 되돌립니다. 서버는 한 행을 한 번에 쓰고(예전엔 필드마다
따로 9번), 일괄 제출은 고른 칸에만 두 번 씁니다. 시트를 고치는 요청은 잠금을 잡고 하나씩
처리해, 거의 동시에 들어온 저장끼리 서로 덮어쓰지 않습니다.

서비스 워커도 캐시를 먼저 내주고 갱신은 뒤에서 합니다. 새 파일이 확인되면
화면에 "새 버전이 준비됐습니다" 알림이 뜨고, 새로고침 여부는 사용자가 고릅니다.

- 서비스 워커는 앱 셸(HTML/CSS/JS)만 캐시합니다. 잔액·목록은 항상 서버에서 새로 받습니다.
- GitHub Pages 는 `cache-control: max-age=600` 을 보냅니다. 그대로 두면 배포 후 10분 동안
  브라우저가 옛 파일을 재검증 없이 내주어, 새 코드가 올라가 있어도 옛 코드가 실행됩니다.
  그래서 서비스 워커는 설치할 때도 실행 중에도 HTTP 캐시를 건너뛰고 원본에 직접 확인하며,
  `sw.js` 자체도 `updateViaCache: 'none'` 으로 등록합니다.
- 화면이 비거나 이상하면 설정 → **최신 버전으로 새로고침** 을 누르십시오. 서비스 워커
  등록과 캐시를 모두 지우고 다시 받습니다.
- 자동 분류는 초안입니다. 저장 전에 항상 화면에서 확인·수정하십시오.

### 같은 내용이 두 번 저장되지 않도록

`fetch` 가 실패했다는 것은 응답을 못 받았다는 뜻일 뿐, 서버가 저장하지 않았다는
뜻이 아닙니다. Apps Script 는 응답에 몇 초가 걸리고 영수증 사진까지 실려 가므로,
서버가 저장을 마친 뒤 응답이 오는 도중에 연결이 끊길 수 있습니다. 그 상태에서
다시 저장하면 같은 내용이 두 번 들어갑니다.

- 앱은 저장 한 건마다 고유한 `요청ID` 를 만들어 보내고, 다시 시도해도 같은 값을 씁니다.
- 서버는 `지출기록`·`정산기록` 의 `요청ID` 열을 보고, 이미 처리한 요청이면 새로 쓰지
  않고 먼저 저장된 것을 돌려줍니다(`중복요청: true`).
- 그래서 네트워크 오류일 때 앱이 **스스로 두 번까지 다시 시도**합니다. 대개 사용자는
  오류를 보지 못한 채 저장이 끝납니다.

`요청ID` 열은 필요할 때 자동으로 만들어지므로 따로 손볼 것이 없습니다.

### 영수증 인식이 실패할 때

예전에는 영수증 분석 요청이 재시도 대상에서 빠져 있어, 위의 요청 되돌림이나 연결 끊김이 한 번만
나도 곧바로 "인식 실패" 가 됐습니다(2026-09-15 두 건). 같은 사진을 나중에 보내면 정상 인식되는
것으로 확인했습니다.

- 앱: 분석 요청도 일시적 통신 오류면 한 번 더 보냅니다.
- 서버: Claude 가 혼잡(529)·요청 한도(429)·서버 오류(5xx)·연결 끊김이면 1.5초·4초 뒤 다시 부릅니다.
  실패하면 원인을 알아볼 수 있는 문장(API 키 오류, 크레딧 부족, 혼잡, 손상된 PDF 등)으로 알려 줍니다.
- 분석을 기다리는 동안 **건너뛰고 직접 입력** 을 누르면 바로 입력으로 넘어가고, 늦게 온 결과는 버립니다.

### 구글이 요청을 되돌려 보낼 때

Apps Script 웹앱은 결과를 별도 주소(`script.googleusercontent.com`)로 넘겨주는데, 가끔 그 주소가
다시 `/exec` 로 되돌려 보내면서 요청 내용이 사라집니다. 몇 분씩 몰려서 일어나기도 하며, 그동안은
리다이렉트를 여러 번 오가다 1분 넘게 걸리거나 404 가 납니다. 예전 서버는 내용 없는 요청에
ping 응답(`ok: true`)을 돌려줘, 앱이 **빈 결과를 성공으로** 받아들였습니다.

- 서버는 내용 없는 요청에 `EMPTY_REQUEST` 오류를 돌려줍니다.
- 앱은 이것과 깨진 응답, 너무 늦는 응답(기본 30초 · 사진 저장 60초 · 영수증 분석 90초)을
  일시적 실패로 보고 다시 보냅니다. 조회와 영수증 분석(시트를 바꾸지 않음)은 항상, 저장은 `요청ID` 가 있는 것만 다시 보냅니다.
- 끝내 결과를 받지 못한 저장은 실패라고 단정하지 않고 "반영됐는지 확인하세요" 라고 알립니다.
  서버에서는 이미 처리됐을 수 있기 때문입니다.
- 앱 아이콘은 Lucide 의 `receipt-text` (ISC License) 를 앱 색상에 맞춰 구성한 것입니다.
  원본은 `web/icons/icon.svg` 이며, PNG 세 종은 이 도형을 캔버스에 그려 만듭니다.
  홈 화면용 PNG 는 모서리를 둥글리지 않은 정사각형입니다 — iOS 가 자체 마스크를
  씌우므로, 미리 둥글리면 모서리가 이중으로 깎여 보입니다.
- 저장소는 공개이지만 접근 토큰·API 키·시트 ID 는 코드에 없습니다. 데이터 접근은
  전적으로 `API_TOKEN` 이 막습니다. 토큰이 새어 나갔다고 판단되면 Apps Script 에서
  `resetApiToken` 을 실행하고 앱에서 새 토큰을 입력하십시오.

## 6. 코드를 고친 뒤

| 대상 | 반영 방법 |
|---|---|
| `web/` | `git push` — Actions 가 자동 배포합니다. `web/app.js` 의 `APP_VERSION` 을 함께 올리면 설정 화면에서 무엇이 돌고 있는지 확인할 수 있습니다 |
| `apps-script/` | `cd apps-script && clasp push` 후 아래 배포 갱신 |

#### Apps Script 배포 갱신

`clasp push` 는 코드를 올릴 뿐이고, **웹앱 URL 은 배포된 버전에 고정**됩니다.
푸시만 하면 URL 은 계속 옛 코드를 실행하므로 반드시 배포를 갱신하십시오.

```bash
cd apps-script
clasp push
clasp list-deployments                       # 배포 ID 확인
clasp deploy --deploymentId <배포ID> --description "무엇을 바꿨는지"
```

Apps Script 편집기에서 하려면 **배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** 입니다.

> **배포는 하나만 유지하십시오.** 배포를 여러 개 만들면 각각 다른 코드 버전에 고정되어,
> 기기마다 다른 URL 을 쓰게 되고 한쪽만 옛 코드로 도는 일이 생깁니다.
> `clasp list-deployments` 결과에서 `@HEAD` 는 Apps Script 가 자동으로 두는 것이라
> 삭제되지 않으며, `/exec` 로 쓰이지 않으니 그대로 두시면 됩니다.
